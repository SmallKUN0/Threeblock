先说说它到底干了什么

它用 Three.js 建了一个"无限海面"——实际上就是相机走到哪，就在周围生成 49 个 70×70 的方块， 走出去了就把远的方块删掉。这个思路（区块系统）本身是对的，问题全在执行细节上。

坑一：像素比不设上限，抗锯齿还开着

const renderer = new THREE.WebGLRenderer({ antialias: true });
renderer.setPixelRatio(window.devicePixelRatio);   // ❌ 没 clamp

这两个加起来就是灾难。devicePixelRatio 在手机上常常是 3，在 Mac 上是 2， 意思是你写 1920×1080 的画布，实际要渲染 5760×3240 的像素——9 倍的像素量。 而抗锯齿（MSAA）是"每个像素再多采几个样"。 两项一叠加，填充率直接爆掉，风扇起飞。 正确写法是 Math.min(devicePixelRatio, 2)，或者干脆锁定 1.5。

坑二：两盏灯都开阴影，而且每帧重算

renderer.shadowMap.autoUpdate = true;   // ❌ 阴影每帧重算，从不缓存
sun.shadow.mapSize.set(2048, 2048);      // ❌ 一张 2048² 的深度图
fillLight.castShadow = true;             // ❌ 第二盏灯也开阴影

阴影是怎么来的？是显卡从"光源视角"把整个场景再渲染一遍，把深度写进一张贴图。 也就是说，两盏灯开阴影 = 每帧多渲染两次整个场景。 而这里阴影范围还设到了 420 单位、贴图 2048²，代价极高。 最致命的是 updateLights() 里光照跟着相机跑， 于是阴影每帧都必须重算——永远没有"静态帧"可以省。

坑三：在 CPU 上逐顶点算波浪，还要每帧重算法线

for (let i = 0; i < pos.count; i++) {
  pos.setY(i, waveHeight(x, z, t));   // 49 块 × 289 个顶点
}
mesh.geometry.computeVertexNormals(); // ❌ 每帧重算法线，新手最经典的性能杀手

49 个区块，每块 16×16 细分 = 289 个顶点，一共约 1.4 万个顶点， 每帧在 JS 里逐个算 4 个 Math.sin——这还只是第一遍。 紧接着 computeVertexNormals() 会再遍历一遍所有三角形， 求叉积、累加、归一化。等于每帧多做了几万次浮点运算，全在主线程上。 这活儿本该交给显卡的顶点着色器做，那里是几万个核心并行算的。

坑四：区块之间故意留缝

const CHUNK_GAP = 7;   // ❌ 故意留出的缝隙
const jx = (Math.random() - 0.5) * CHUNK_GAP;  // ❌ 随机错位

所以你在页面上看到的不是"无限海面"，而是一片海上拼图—— 方块之间有 7 单位的空隙，还随机错位，永远对不齐。 真正的无限海面必须做到"无缝"：要么所有顶点都用世界坐标采样噪声， 要么相邻区块共享边界顶点。这里是两头都不占。

坑五：贴图关掉了 Mipmap，远处疯狂闪烁

tex.generateMipmaps = false;   // ✅ 按要求禁用 Mipmap
tex.minFilter = THREE.LinearFilter;

Mipmap（不是 Minmap，拼错了）是什么？简单说，就是给同一张图预先准备 一系列越来越小的版本（1/2、1/4、1/8……），显卡根据物体离你多远， 自动挑一个尺寸合适的版本去采样。

不生成 Mipmap 会怎样？想象一张 256×256 的贴图被压缩到屏幕上只有 10 个像素， 显卡只能从原图里随便抓几个像素点——相邻像素抓的位置差很远， 结果就是远处的水面像电视机雪花一样疯狂闪烁，这叫"摩尔纹"， 走路的时候尤其明显。这就是为什么专业引擎里 Mipmap 是默认开启的。

坑六：水面用双面渲染

side: THREE.DoubleSide

水面是双面的，意味着每个像素都要画两次（正面一次背面一次）， 填充率直接翻倍。而这效果几乎没有——除非你打算潜到水下往上看。

还有：没有雾

代码里 scene.fog = null。于是区块边缘是一条硬生生的直线切在远处的背景色上， 玩家一眼就能看到"世界的边界"。真正的无限海面必须靠雾把远景融进天空里。

小结：新手的代码"能跑"，但每一帧都在做三件不该做的事—— 重算阴影、CPU 算波、重算法线。这三件事任何一件单独拿出来，都能让帧率掉一半。 不过话说回来，能把它跑起来、能看到海，已经比 90% 半途而废的人强了。

第一大进步：不用框架，直接开着色器

新手那一版是靠 Three.js 这个"框架"在帮你干活。中手这版直接 canvas.getContext('webgl2')，从零开始： 自己编译着色器、自己建缓冲区、自己算矩阵。这是从"用工具的人"变成"造工具的人"的分水岭。

那"着色器"到底是什么？

你可以把它想象成一段由显卡执行的程序。它分两种：

  • 顶点着色器：每个顶点跑一次。它的任务是"决定这个顶点最终出现在屏幕的哪个位置"。 在这里你可以任意修改顶点的高度——这就是"实时生成波浪"的原理。
  • 片元着色器：每个像素（更准确说是每个"候选像素"）跑一次。 它的任务是"决定这个像素是什么颜色"。在这里你可以采样贴图、算光照、算反射。

它们一般用在哪？游戏、影视、数据可视化、UI 特效、滤镜、粒子系统……几乎所有的实时图形。 关键点在于：顶点着色器是几千几万个核心同时跑的， 所以你把"算波浪"这件事从 CPU 挪到顶点着色器，速度能快几十上百倍。 新手那一版的性能瓶颈，本质上就是"该让 GPU 干的活让 CPU 干了"。

区块系统 + 实例化绘制

const CHUNK_SIZE = 32.0;
const VIEW_R     = 7;      // 半径 7 → 15×15 = 225 个区块
const MAX_INST   = (VIEW_R * 2 + 1) * (VIEW_R * 2 + 1) + 8;

区块（Chunk）系统是什么？就是把无限大的世界切成一块一块的方格， 只渲染你身边那几块，走出去就把后面那块扔掉、前面那块造出来。 这是所有开放世界游戏（Minecraft、塞尔达、原神）都在用的基础套路。

中手这里比新手聪明的地方在于：他不是造 225 个独立的网格， 而是造一个网格，然后告诉显卡"把这个网格在 225 个位置上各画一遍"。 这叫实例化绘制（drawElementsInstanced）， 它的开销基本等于画一次，而不是画 225 次。这是 WebGL2 相对 WebGL1 最重要的升级之一。

波浪：四层正弦叠加，问题就出在这

d = vec2(0.86603, 0.50000); k = TAU / 26.0; a = 1.10;
ph = dot(d, p) * k + t * 0.80;
h += a * sin(ph);  grad += d * (k * a * cos(ph));

这四组波的方向、波长、速度全是硬编码的。 正弦函数是周期的、对称的、可预测的——所以你在页面上盯着看几秒，就会发现 "哎，这个浪刚才是不是出现过？" 而且波峰是一条条笔直的平行线，完全没有真实海面那种忽高忽低、忽宽忽窄的随机感。

这就是中手和高手最大的分水岭：中手觉得"能算出高度就是波浪了"， 高手知道"必须让高度场看起来毫无规律"。

聪明的地方：解析法线，不重算

注意 grad += d * (k * a * cos(ph)) 这一行—— 他在叠加波浪的同时，顺手把"这个点朝哪个方向倾斜"（梯度）也算出来了。 因为正弦的导数是余弦，是解析解，一次乘加就完事。 这比新手那种"每帧把几万个三角形叉积一遍"快了不止一个数量级。 这才是把数学用对地方的典范。

伪 3D 法线贴图：不是真 3D，但是够用

vec2 uv1 = v_world.xz * 0.060 + vec2( u_time * 0.0110,  u_time * 0.0070);
vec2 uv2 = v_world.xz * 0.150 + vec2(-u_time * 0.0140,  u_time * 0.0100);
vec3 n1 = texture(u_normalMap, uv1).xyz * 2.0 - 1.0;

法线贴图是什么？就是一张"存着每个像素该朝哪边倾斜"的图片。 它的 RGB 三个通道分别存了 x、y、z 三个方向的倾斜分量。 主网格的顶点数有限，撑不起细小的涟漪，那就用一张贴图去"假装"有细节。

这里用两层不同缩放、不同流动速度的采样叠加，就是为了打破重复感。 纹理是 CPU 端用值噪声多倍频生成的 256×256 图。

Mipmap + 距离细节剔除

gl.generateMipmap(gl.TEXTURE_2D);
gl.texParameteri(gl.TEXTURE_2D, gl.TEXTURE_MIN_FILTER, gl.LINEAR_MIPMAP_LINEAR);

float detail = 1.0 - smoothstep(25.0, 170.0, dist);

Mipmap 前面讲过，就是给贴图准备一串越来越小的副本，远处自动用小的， 既防闪烁又省带宽。这里还加了一手：超过 170 单位，法线贴图的扰动权重直接归零—— 反正那么远的细节你也看不见，不如省掉。

LOD（Level of Detail，细节层级）就是这个思路的正式名字： 离得近用高精度，离得远用低精度。中手在这里用的是最粗暴的 LOD——"要么有，要么没有"， 不像老手那样做渐进过渡。

反射：用一个函数"算"出来的天空

vec3 R = reflect(-V, N);
vec3 reflCol = skyColor(normalize(R));

注意它不是真的去渲染一张环境贴图，而是用一段数学公式现场算出天空该是什么颜色。 这种"解析式反射"的代价几乎为零，但只有天空是纯渐变时才好看。 算是个性价比很高的取巧。

天空：一个三角形画满全屏

vec2 p = vec2(float((gl_VertexID << 1) & 2), float(gl_VertexID & 2));
gl_Position = vec4(p * 2.0 - 1.0, 1.0, 1.0);

这段是个小魔法：不传任何顶点数据，靠 gl_VertexID（顶点编号 0/1/2） 算出一个盖住整个屏幕的三角形。比传两个三角形的顶点省一点， 但更重要的是"优雅"。属于写 WebGL 的人一看就会心一笑的那种技巧。

小结：中手是真的跨过门槛了——他懂性能、懂 Mipmap、懂实例化、懂解析法线。 但他还没意识到"海浪的本质是随机"。四个正弦波能骗过远处的眼睛， 骗不过盯着看三秒的人。4 分的话，给他 3 分，剩下 2 分留给"随机性"。

高手已经把"规则波形"这道坎彻底跨过去了——代码里一个 sin 都找不到。 而且他干了一件特别漂亮的事：把整个区块系统都给干掉了， 只用一张 161×161 的网格就铺满了半径 3000 的海面。这招叫什么？叫"连续 LOD"。

直接输出代码。

最惊艳的一招：不用区块，却铺满 3000 单位

vec2 a = abs(aUV);
vec2 w = (exp(a * 5.0) - 1.0) * 0.0067836;   // 1/(e^5-1)
vec2 offset = sign(aUV) * w * 3000.0;        // 渲染半径 3000

看懂了这段，你就理解了什么叫"连续 LOD"。

网格顶点原本均匀分布在 -1 到 1 之间。这段代码把它做了个指数映射： 靠近中心的顶点几乎没怎么动（密密麻麻挤在脚下），越往外，被拉伸得越厉害（稀稀拉拉铺到天边）。

结果就是：一张 161×161 的网格，脚下精度极高，天边精度极低，中间平滑过渡，完全没有缝。 区块系统带来的"边界、销毁、重建、接缝"这一整套麻烦，一次性全没了。

这招的代价是：顶点分布不均匀，边缘的三角形被拉得很长，会有轻微的拉伸感。 但对于海面这种高频细节的东西，肉眼看不太出来。非常划算。

波浪：三层梯度噪声 + 域扭曲，一条正弦都没有

vec2 warp = vec2(
  gnoise(p * 0.0055 + vec2(t * 0.060, 0.0)),
  gnoise(p * 0.0055 + vec2(0.0, t * 0.070) + 19.3)
) * 60.0;
vec2 q = p + warp;

h += gnoise(q * 0.0100 + vec2( t * 0.220,  t * 0.140))        * 13.0;
h += gnoise(q * 0.0270 + vec2(-t * 0.380,  t * 0.260) + 7.1) *  5.0;
h += gnoise(q * 0.0680 + vec2( t * 0.620, -t * 0.450) + 3.3) *  1.7;

梯度噪声（gradient noise，柏林噪声是它最出名的一种）的原理是： 在格子上放随机的"方向向量"，然后看某个点朝各个方向投影多少，做插值。 它的特点就是——没有周期，看起来完全随机，而且天然平滑。

三层不同频率叠加（大的 13、中的 5、小的 1.7）就是所谓的 FBM（分形布朗运动）， 模拟自然界的"大结构套小结构"。

最妙的是 域扭曲（domain warping）：先用噪声算出"该往哪边偏"，再去采样波浪。 相当于把整片海面"揉皱"了一下。这一步让波峰从"圆圈"变成了"弯曲的、不规则的浪脊"， 是让它看起来不那么"程序生成"的关键。

而且注意每层的 t * 0.220 这种系数——它的意思是"这个噪声场自己在流动"。 所以水面是"整体在动"，而不是"贴图在滚"。

法线：有限差分，三次采样搞定

const float E = 1.0;
float h0 = waveH(xz, uTime);
float hx = waveH(xz + vec2(E, 0.0), uTime);
float hz = waveH(xz + vec2(0.0, E), uTime);
vec3 nrm = normalize(vec3(-(hx - h0) / E, 1.0, -(hz - h0) / E));

高度函数的导数没法直接写出来（噪声嘛），那就"取两个很近的点，算斜率"。 这就是有限差分。E = 1.0 是采样间距，越小越精确，但太小会浮点误差。

代价是：每个顶点要算三次波浪，而不是一次。但比起新手的 computeVertexNormals()，这仍然是天上地下——后者要把所有三角形叉积一遍。

片元里再叠一层噪声法线

float fade = 1.0 - smoothstep(150.0, 900.0, dist);
float h0 = gnoise(p);
float hx = gnoise(p + vec2(e, 0.0));
float hz = gnoise(p + vec2(0.0, e));
N = normalize(N + vec3(-g.x, 0.0, -g.y) * (0.09 * fade));

顶点密度有限，撑不起"水面上那些细碎的小坑"。所以在片元着色器里， 对每个像素再算一遍噪声梯度，叠加上去。配合 fade，远处自动淡出省性能。

不足的地方

  • 没有真正的天空，反射用的是解析公式，云、太阳圆盘都没有。
  • 没有泡沫，浪尖永远是干净的水。
  • 没有次表面散射，浪尖不会透光，看起来偏"塑料"。
  • 雾用的是 smoothstep(900, 2800)，过渡还行，但雾色是写死的常量，和天空对不齐。
小结：高手的核心贡献是"连续 LOD 网格"和"纯噪声高度场"这两件事。 技术上已经非常漂亮了，剩下的差距全在美学上—— 他还没开始琢磨"太阳该怎么画""云该怎么堆""浪尖该不该透光"。 4 分，实至名归。

核心突破：3D 噪声图集（Noise Atlas）

先解释一下"3D 纹理"是什么。普通贴图是二维的（x、y），3D 纹理是三维的（x、y、z）。 好处是：你可以把 z 当成"时间"或者"深度"，让纹理在三维空间里平滑地滚动。 

const ATLAS_SIZE = 64;     // 图集总尺寸
const TILE_SIZE  = 32;     // 每个小块 32³
// 64³ 的盒子切成 2×2×2 = 8 个 32³ 的小块

为什么叫"图集"？因为它把 8 块不同的噪声打包进同一张纹理的不同区域， 就像把 8 张小照片拼成一张大合照。这样只需要绑定一次纹理、采样一次坐标， 就能拿到想要的任何一块。

四个通道，八种细节

data[k++] = (fR(wx, wy, wz) * 255) | 0;              // R 主起伏（低频）
data[k++] = ((1 - Math.abs(2 * rg - 1)) * 255) | 0;  // G 脊状（坑洞）
data[k++] = (fB(wx, wy, wz) * 255) | 0;              // B 中频细波
data[k++] = (fA(wx, wy, wz) * 255) | 0;              // A 高频细碎

一张 RGBA 纹理有四个通道，每个通道塞一种噪声。再配合 8 个 tile， 理论上一次纹理绑定就能拿到 32 种不同的噪声形态。这是极致的"打包"思维。

注意 1 - Math.abs(2n - 1) 这个变换——这就是脊状噪声 （ridged noise）。普通的噪声是"平滑的丘陵"，经过这个变换之后会变成 "尖尖的山脊和深深的沟"，特别适合做水面上的坑洞和泡沫边缘。

textureGrad：让 Mipmap 在"手动采样"时也正确

vec3 origin = vec3(float(idx & 1), float((idx >> 1) & 1), float((idx >> 2) & 1));
vec3 uv = origin * 0.5 + local * 0.5;
vec3 d  = dLocal * 0.5;
return textureGrad(uNoiseTex, uv, d, d);

这里解决了一个很隐蔽的问题：正常采样时显卡会自动算"这个像素在纹理上跨了多大面积"， 然后挑合适的 Mipmap 层级。但因为我们在这里做了坐标变换 （把局部坐标映射到图集的某一格），显卡的自动计算就失效了， 只能落到最粗糙的层级，结果就是细节全糊成一坨。

textureGrad 允许你手动告诉显卡"变化率是多少"， 这样它就能算对层级。这是真正写过硬核着色器的人才知道的坑。

第一个大跨越：从"直接画到屏幕"到"HDR 管线"

前面几位的做法都是：算完颜色，直接 fragColor = vec4(col, 1.0)，结束。 问题在于屏幕只认得 0 到 1。太阳那么亮，写 50 也好、写 500 也好，最后全被砍成 1， 看起来就是一块死白，没有任何层次。

HDR（高动态范围）的思路是：先用一张"能存超过 1 的数值"的画布（浮点纹理）把场景画出来， 太阳就是 34、高光就是 46，全存着；最后再统一"曝光 + 压缩"成屏幕能显示的 0 到 1。 

const extCBF = gl.getExtension('EXT_color_buffer_float');
const COLOR_FMT  = extCBF ? gl.RGBA16F : gl.RGBA8;
const COLOR_TYPE = extCBF ? gl.HALF_FLOAT : gl.UNSIGNED_BYTE;

这就是在说："如果显卡支持浮点渲染目标，我就用 16 位浮点；不支持就退回 8 位。" 专业做法，兼容性拉满。

泛光（Bloom）：让亮的地方"溢出来"

泛光的原理其实很朴素：把画面里特别亮的像素抠出来，糊一糊，再盖回去。

  • 亮部提取：亮度超过阈值 0.85 的才算数，其余归零。
  • 降采样 + 高斯模糊：连续 4 级，每级尺寸减半，越往下糊得越开。
  • 合成：四级模糊结果按不同权重叠回原图。

为什么要分 4 级？因为如果只糊一次，光晕会很小很硬。分成多级叠加， 就得到了"近处一圈紧贴的亮边 + 远处一大片柔和的光雾"， 这就是真实的相机镜头在强光下会有的那种感觉。

ACES 色调映射：为什么专业渲染器都用它

vec3 aces(vec3 x){
  const float a = 2.51, b = 0.03, c = 2.43, d = 0.59, e = 0.14;
  return clamp((x * (a * x + b)) / (x * (c * x + d) + e), 0.0, 1.0);
}

这段看着像天书，其实就是一个精心调校过的"曲线"。 它的作用是：把 HDR 里巨大的数值范围，优雅地压进 0 到 1， 同时——关键在这里——暗部不会死黑，亮部不会死白，中间过渡很自然。

ACES 是电影工业协会搞出来的标准，好莱坞调色几乎全靠它。 用了它，你的画面立刻就有一种"电影感"，而不是"网页 demo 感"。

写实的太阳：算的是"角度"，不是"点积"

float cosA = clamp(dot(d, uSunDir), -1.0, 1.0);
float ang  = acos(cosA);
float sunR = 0.0058;
float r    = ang / sunR;

float mu   = sqrt(max(0.0, 1.0 - min(r,1.0) * min(r,1.0)));
float limb = 1.0 - 0.62 * (1.0 - mu);

前面几位画太阳，都是 pow(dot(d, sunDir), 几百)——一个模糊的光斑而已。 大超手这里用的是真实的角度：真实太阳的角半径是 0.00465 弧度， 这里稍微放大到 0.0058，让它在屏幕上有几个像素。

然后 limb 是临边昏暗（limb darkening）——真实太阳的边缘比中心暗大约 50%， 因为边缘的视线穿过的是太阳大气的斜切面。这个物理效应一加上， 太阳立刻从"一个白点"变成了"一颗球"。

云：三层，三个高度，三种形态

float t1 = 1500.0 / d.y;   // 低层积云：1500 米高
float t2 = 4300.0 / d.y;   // 高层卷云：4300 米高
float t3 = 9000.0 / d.y;   // 极高空薄纱：9000 米高

这个 1500.0 / d.y 是经典的"平面求交"技巧： 假设云都在高度 1500 的平面上，你朝某个方向看，视线和这个平面交在哪，就从哪采样。 视线越接近水平（d.y 越小），交得越远，云就显得越"铺展"——这正好符合现实。

海洋：三层结构，全部在顶点着色器

  • ① 宏观涌浪：用极低频 FBM，中心差分求梯度，模拟几百米尺度的起伏。
  • ② 域扭曲：用两层慢变噪声偏移采样坐标，波峰不再排成直线。
  • ③ 8 组 Gerstner 波：全向随机方向，波长按 0.70 递减，相位带缓慢漂移。
  • ④ 2 组细波：波长 72 和 45，负责更细的几何起伏。

Gerstner 波和普通正弦波的区别在于：它不只是上下动，还会在水平方向"推"顶点。 所以波峰会变得尖锐、波谷会变平缓——这正是真实海浪的形状。

法线更讲究：不靠有限差分，而是维护了两个切向量 t1、t2， 每叠一层波就更新一次雅可比矩阵，最后 cross(t2, t1) 一步得到精确法线。 这比有限差分省事，而且更准确。

前面五位都在"用三角形拼出海面，然后给三角形上色"。 这位直接说：不要三角形了。

思路是：从一个像素射出一条光线，沿着这条光线一小步一小步往前走， 每走一步就问一句"我现在是在水面之上还是之下？"（p.y - waveHeight(p.xz)）。 第一次变成"之下"的时候，就说明刚才那一步跨过了水面。 然后再在这最后一步的区间里二分 5 次，就能精确找到交点。

焦散（Caustics）：水底那些跳动的光斑

去海边的时候，浅水底下会有那种一张网一样、不停跳动的亮纹对吧？那就是焦散。

它的物理本质是：水面像一块不断变形的透镜，把阳光聚焦成一条条亮线。 数学上，聚焦点出现在"曲面曲率最大"的地方。

这里的做法比较取巧但很有效：用脊状噪声（1 - abs(2n-1)）做出网格状的亮纹， 再用一个正弦干涉项（1 / (1 + 3|lap|)）让它看起来更像"焦线"而不是普通的噪点。 两层叠加 + 时间推进，就有了那种"活着的"光斑。

比尔-朗伯吸收：翡翠色的物理来源

vec3 absorbCoef = vec3(0.95, 0.24, 0.17);
vec3 transmittance = exp(-absorbCoef * tFloor * 0.052);

这是一个真实存在的物理定律：光穿过介质时，强度按指数衰减，而且不同波长衰减不一样。

看这组系数：红光衰减 0.95（最快），绿光 0.24，蓝光 0.17（最慢）。 意味着光穿过一段水之后，红光被吃掉了，剩下绿光和蓝光—— 这就是为什么浅海是翡翠绿、深海是深蓝。

这不是"调一个好看的颜色"，这是"从物理规律里推导出颜色"。层次完全不一样。

GGX 微表面模型：让高光拖出长条

真实水面不是光滑的镜子，上面有无数细小的波纹。光线打上去会朝各个方向散开， 形成一片"高光带"，而不是一个亮点。要模拟这个，就得用微表面理论。

微表面模型由三部分组成，也就是提示词里说的 D、G、F：

  • D（法线分布函数）：描述表面上有多少比例的微小面朝某个方向。 GGX 是最常用的一个，特点是"长尾巴"——也就是说， 高光核心很亮，但边缘会拖得很远很淡。这就是"各向异性拖尾"的来源。
  • G（几何遮蔽）：描述微小面之间互相遮挡的情况。 你不该看到被别的凸起挡住的那些面的反光。
  • F（菲涅尔）：描述"看的角度越斜，反射越强"。 这就是为什么水面永远在你脚下时是透明的，在远处地平线时是镜面的。

三者相乘，再除以一个归一化因子，就得到了物理正确的镜面反射。 这套公式本来是给电影渲染用的，被搬进浏览器了。

粒子系统：飞溅的水花

uniform vec4 uParticles[64];

CPU 端维护 64 个粒子（位置、速度、半径），每帧做重力抛物线和"撞到水面就消失"的判定， 然后把数据打包成 uniform 数组丢给着色器。

着色器端对每个粒子做一次射线-球体求交，算出这个像素是不是被粒子挡住了， 如果是，就加上粒子颜色和柔和的边缘。

只有 64 个粒子，纯 CPU 管理完全够用。这是"能用简单办法就别上复杂办法"的体现。
